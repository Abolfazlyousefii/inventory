## تصمیم فعلی و پیش‌نمایش اصلاح

**نیازمند تأیید فیزیکی؛ اجرا ممنوع تا تأیید صریح مالک.**

۱. مسئول انبار، تعداد واقعی و محل فعلی هر تنوع را با صورت‌جلسه تأیید کند.
۲. سوابق انبارگردانی، انتقال و اصلاح دستی هم تطبیق داده شود تا موجودیِ قبلاً شمارش‌شده دوباره اضافه نشود.
۳. اگر کمبود ثبت ورود اثبات شد، پیشنهاد اصلاح با رسید واقعیِ تأییدشده، ارجاع به سند/ردیف اصلی، دلیل و کاربر تأییدکننده ارائه شود؛ نه ویرایش مستقیم موجودی.
۴. اصلاح پیشنهادی از نظر مالی خنثی باشد: **بستانکاری جدید مشتری صفر**؛ ثبت ۳۸۱۶ حفظ شود.
۵. اگر کالا موجود نیست، موجودی مصنوعی ساخته نشود. اگر تعداد واقعی متفاوت است، تصمیم مالی جداگانه لازم است.

ابزار پیش‌نمایش صرفاً خواندنی است و گزینهٔ اعمال ندارد:

```powershell
php artisan returns:audit --dry-run --sales-return=432 --purchase-return=00004 --json
```

در Production این دستور فقط پس از نصب تأییدشدهٔ کد قابل استفاده است. ممیزی این مأموریت با بارگذاری مستقل همان سرویس، خارج از مسیر برنامهٔ عملیاتی و داخل تراکنش `READ ONLY` انجام شد.
